## Method

For each active alpha subnet at both exact block hashes:

- Actual staked alpha = `sum(TotalHotkeyAlpha(hotkey, netuid))`.
- Pending alpha = split server/validator pending or legacy `PendingEmission`, plus `PendingRootAlphaDivs + PendingOwnerCut + PendingBasketDeposits`.
- Calculated staked alpha = `SubnetAlphaOut - AlphaBurned - pending alpha - SubnetProtocolAlpha`.
- Signed discrepancy Δ = `actual staked alpha - calculated staked alpha`.
- Discrepancy movement = `Δ(later) - Δ(earlier)`.

PendingBasketDeposits read mode: raw runtime-447 storage keys. Historical runtimes that predate this storage item are measured from the still-present runtime-447 raw keys.

Subnet pending-emission read mode: legacy PendingEmission plus frozen runtime-447 PendingServerEmission/PendingValidatorEmission. For legacy runtimes, the live historical `PendingEmission` liability is added to the frozen synced-state `PendingServerEmission` and `PendingValidatorEmission` liabilities.

SubnetProtocolAlpha read mode: raw frozen runtime-447 storage keys. When candidate metadata predates this storage item, the still-present runtime-447 values are retained as a frozen baseline term. Their constant offset preserves comparison with the current residual and cannot create or hide discrepancy movement.

The “above baseline” marker is comparative, not a tolerance in the accounting formula. It uses the preceding adjacent-block measurement of 2–3 rao per block to identify movements too large to be explained by that observed drift.
